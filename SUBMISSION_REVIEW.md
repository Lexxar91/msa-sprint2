## Объём изменений

Из авторских исходников, Dockerfile, Makefile, SQL, protobuf-контрактов и конфигураций удалены обычные поясняющие комментарии. Служебные директивы, документация, сгенерированные модули, зависимости, Gradle Wrapper и исторические результаты сохранены.

Добавлены корневой README со схемами и командами запуска, настройки форматирования и исключения файлов сборки/зависимостей из Git. Новые результаты проверок сохранены отдельно от прежних журналов.

Существующие контейнеры и Minikube не пересоздавались, Kubernetes-релизы не обновлялись. GitHub Actions и повторный тест canary/fallback в кластере в этой проверке не запускались.

## Что остаётся для полной готовности

1. **Task3:** подграф отелей должен обращаться к внешнему сервису; сейчас возвращаются заглушки. После gRPC `reject` отсутствует ранний выход — возможна ошибка обращения к пустому ответу. Изменение логики исключено из текущей задачи.
2. **Task2:** исходное задание требует Kafka; реализован RabbitMQ. Отклонение описано в ADR, но требует согласования с проверяющим.
3. **Task4:** исходное задание требует GitLab CI; по выбору пользователя реализован GitHub Actions. Сохранён неиспользуемый GitLab-черновик.
4. **Артефакты task3:** сохранены фактические JSON-ответы, docker ps и логи. Скриншоты, указанные в задании, ещё нужно приложить, если формат проверяется строго.
5. **Доставка событий:** запись бронирования и публикация в RabbitMQ не объединены transactional outbox. Сбой публикации после сохранения не откатывает бронирование.
6. **Зависимости Node.js:** при сборке npm предупреждает об устаревших Apollo Server 4 и ряде транзитивных пакетов. Обновление зависимостей в эту подготовку не включено.
7. **Старый Compose монолита:** `hotelio-monolith/docker-compose.yml` ссылается на отсутствующий Dockerfile. Корневой README использует рабочий `tasks/docker-compose.yml`.

Документация и стиль подготовлены, перечисленные проверки пройдены. Полное соответствие исходному заданию не подтверждено из-за указанных функциональных и формальных расхождений.
